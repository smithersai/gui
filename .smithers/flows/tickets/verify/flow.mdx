---
description: Verify one .smithers/tickets ticket's acceptance criteria against the code and tests, and report each criterion as shipped, partial, or missing with file evidence.
capabilities: ["fs:read:**", "fs:write:.smithers/reports/ticket-verify.json", "proc:spawn:rg *", "proc:spawn:jj --no-pager *"]
model: sol
budget:
  tokens: 64000
  milliseconds: 900000
---

The input names one ticket: a number such as `0158` or a path under
`.smithers/tickets/`. Read the ticket as data. Do not edit tickets, source,
or tests, and do not run builds.

1. Extract each acceptance criterion, or each numbered requirement when the
   ticket has no acceptance section. Note any `Status` the ticket claims.
2. For each criterion, search the repository with `rg` and read the code and
   tests that would satisfy it. A criterion is `shipped` only when the code
   exists and a test exercises it, `partial` when code exists without a test
   or covers only part of the criterion, and `missing` otherwise.
3. Work that belongs to another repository (for example plue backend routes)
   is `out-of-repo`: name the repository and the evidence you would need.
4. Use `jj --no-pager log` to cite the change that landed shipped work.

Write only `.smithers/reports/ticket-verify.json`:
{"ticket":"0158","claimedStatus":"PARTIAL","verdict":"partial","criteria":[{"text":"...","status":"shipped|partial|missing|out-of-repo","evidence":["path:line"],"change":"change id or null"}],"summary":"one sentence"}
Never mark the ticket shipped unless every in-repository criterion is shipped.
